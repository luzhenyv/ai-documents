# EP11｜回到命令行：为什么最强的 AI，在黑窗口里敲命令

> **本集一句话**：文本是最古老的接口，也可能是最通用的接口。人类花了几十年让电脑变得好用，AI 却把我们带回了命令行。

## 口播稿

### 一、钩子：一个有趣的反转

人类花了几十年的时间，发明了鼠标，发明了窗口，发明了触摸屏，就是为了让电脑越来越好用，越来越“傻瓜”。

结果到了 AI 时代，你会发现一件很有意思的事：今天最强的那些 AI 编程助手，干活的地方居然是一个**黑乎乎的窗口**，在里面一行一行地敲命令。

【配图】左边：苹果 Macintosh 1984 年的广告画面，鼠标和图标；右边：今天一个 AI 助手在终端里飞快滚动命令。中间一个大大的“？”。

为什么？

### 二、拆开它：给 AI 一千个工具，还是一个？

模型会调用工具以后，人们马上遇到一个问题。

如果我们想让一个 AI 什么都能干，那是不是要给它配一千种工具？写文档一个工具，定闹钟一个工具，发邮件一个工具……

工具一多，问题就来了。模型在挑工具之前，得先知道自己有哪些工具。几十个还好，几千个、几万个之后，它自己也会晕，很可能挑错。这很正常，**选择太多，本身就是一种负担**。有朋友说得好：决策是很耗能的。你想想你的一生，其实都在做决策，而在几千个选项里做决策，更累。

那能不能反过来，**给它一个足够通用的工具**？

有一个工具，人类用了几十年，它几乎取代了成百上千种别的工具：计算器、算盘、相机、纸和笔、CAD 图纸、各种报表……

这个工具就是**计算机**本身。

【配图】动画：一桌子杂物（算盘、计算器、胶卷相机、稿纸、绘图尺、打字机）一件一件“飞进”一台电脑的屏幕里。

所以就有人冒出了一个大胆的想法：**能不能直接让模型操作计算机？**

然后大家发现，真的可以。

### 三、往下挖：在窗口之前，人是怎么用电脑的

这就要说到，在 Windows 这样的窗口界面出现之前，人是怎么用电脑的？

**命令行。** 在一个黑窗口里，敲各种各样的命令。

比如你想进入某个文件夹，就敲 `cd`，change directory，后面跟上路径。想复制一个文件，就敲 `cp`，copy，后面跟上从哪里复制、复制到哪里。

【补充】比如，我想把桌面上的 `text.txt` 复制到“文档”文件夹，同时改名叫 `text1.txt`：

```
cp ~/Desktop/text.txt ~/Documents/text1.txt
```

**一行命令，复制加改名，一步完成。**【/补充】

【校注】原话的例子是 Windows 的 C 盘、D 盘，但用的是 Unix 的 `cp` 命令（Windows 下对应的是 `copy`）。这里统一改成 Mac / Linux 的写法，也和今天 AI 编程助手常见的环境一致。

那如果用鼠标呢？你得先找到这个文件，右键复制，再打开目标文件夹，粘贴，再右键重命名，打字。好几步。

【配图】分屏计时对比：左边鼠标操作五六步，右边一行命令；两边同时开始，右边早早结束，屏幕打出“1 行 vs 6 步”。

那时候的程序员，电脑旁边常常放一张 A4 纸，上面密密麻麻写满了各种命令的用法。看起来很难，但一旦记熟了，干活飞快。

所以其实你会发现，命令行可能是人类设计过的**最强大、最简洁的一种“语言”之一**。今天我们用的窗口界面，某种意义上是命令行能力的一个**子集**，一种“降级”。为了让普通人也能用，它把很多功能藏起来了。这也是为什么今天很多专业软件，依然保留命令行操作。

有朋友这时候问：可我们现在用的都是界面，界面跟命令行不一样呀。对，界面是给人用的，它追求的是 user friendly，对人友好。但 **AI 不需要这种友好**。它不怕记不住命令，也不怕看一堆文字。

### 四、命令行的秘密：一切都是文本

命令行还有一个特别重要的特点：**它的输入和输出，全都是文本。**

在窗口界面里，你打开一个文件夹，是用眼睛看到它“打开了”；复制成功了，你看到一个进度条。这些都是**图形**。

而在命令行里，一切都是**一行行文字**。你让它列出文件夹里的东西，它就打印一串文件名；出错了，它就打印一行报错。

【校注】原话说“命令行的输入输出是一种文档”，更准确的说法是“**文本流**”：程序从标准输入读文字，往标准输出和标准错误写文字。另外原话举例说“cd 到 D 盘，它会打印‘欢迎来到 D 盘’；复制成功会输出一段话”。实际上 Unix 有一条传统叫“**沉默是金**”：命令成功时往往什么都不说，只有出错时才说话。

【补充】这个“沉默是金”其实很有意思：对一个 AI 来说，**没有消息就是好消息**；一旦出了一行字，那多半就是它该注意的地方。【/补充】

还有，几乎每一个命令都自带一份**说明书**。你敲 `man cp`，或者在很多命令后面加上 `--help`，它就会用文字告诉你：这个命令怎么用，有哪些参数。

这些说明书，当年是写给人看的。今天，大模型也能读。

而大模型最擅长的是什么？**就是读文本、写文本。**

所以大模型甚至不需要专门学怎么用每一个命令。它只需要知道：我可以用命令行。遇到不会的命令，它自己敲一下 `man` 或者 `--help`，读一读说明书，就知道怎么用了。然后执行，看输出，成功了就继续，失败了就读报错，再试。

你可以想象，这就像一个非常有经验的、上古时代的工程师，坐在那台黑色终端前面干活。

### 五、管道：花园里的水管

命令行还有一个非常了不起的设计，叫**管道**。

1964 年，贝尔实验室的**道格拉斯·麦克罗伊**写了一张备忘录，里面有一句话后来特别有名：

> 我们应该有办法把程序像**花园里的水管**一样接起来：这一段拧上另一段。

【配图】麦克罗伊 1964 年备忘录的扫描件，画面叠上一截截能拧在一起的花园水管。

后来在 1969 年诞生的 **Unix** 系统里，这个想法变成了现实。它用一根竖线 `|` 表示管道：**前一个命令的输出，直接变成后一个命令的输入。**

【补充】举个例子。我想知道我的口播稿里，一共有多少行提到了“Skill”这个词：

```
cat 口播稿.md | grep "Skill" | wc -l
```

- `cat`：把文件内容读出来；
- `grep`：从里面挑出含有“Skill”的行；
- `wc -l`：数一数一共有几行。

三个小工具，每个只干一件小事，用两根“水管”一接，就解决了一个新问题。【/补充】

【配图】三个小盒子排成一行，中间用水管连接：文件内容从左边流进 `cat`，流经 `grep` 被过滤，最后流进 `wc`，右边吐出一个数字。

这就是著名的 **Unix 哲学**：**每个程序只做好一件事；程序之间用文本互相连接。**

因为大家说的都是同一种“语言”，也就是文本，所以任何一个程序的输出，都可以接到任何另一个程序上。再往后，人们把一串一串的命令写成文件，就成了 **Shell 脚本**，一种最朴素的编程。

### 六、为什么 AI 回到了命令行

好，现在我们可以回答开头的问题了。我觉得至少有三个原因。

**第一，模态匹配。** 命令行是文本进、文本出；大模型也是文本进、文本出。严丝合缝。

**第二，可组合。** 管道和脚本让几个小工具组合出无数种能力，AI 不需要一千个专门的工具，一个终端就够了。

**第三，也是最容易被忽略的：AI 读过。** 互联网上有几十年积累下来的命令行教程、说明书、问答帖子、脚本代码，它们全都进了模型的训练数据。模型会用命令行，很大程度上是因为**它读过的命令行，比任何一个程序员都多**。

【补充】第三点其实揭示了一件事：**模型会什么，很大程度上取决于它读过什么。** 命令行碰巧是人类留下文字记录最多的一种“操作电脑的方式”。【/补充】

所以今天所谓的 Agent，最简单的理解就是：**给大模型配一台电脑，准确地说，是配一个终端。** 它会说话，会输出结构化的命令，会调工具，会拆任务，会判断任务完成没有；而命令行又是一个天然用文字说话的地方，用文字告诉它成功了还是失败了，用文字告诉它这个工具怎么用。于是，AI 就可以通过这个五十年前的工具，来操作你的电脑了。

【配图】一个 AI 小人坐在一台老式绿字终端前，身后的书架上堆满了发黄的 man 手册。

当然，也有另一条路。有的 AI 直接“看”屏幕截图，然后像人一样移动鼠标、点击按钮，这叫 **Computer Use**。它的好处是，任何给人设计的软件它都能用；坏处是慢，而且容易点错。

**两条路线，谁会赢？** 现在还不好说。但至少到今天，文本这条路走得更快。

### 七、往上看：工具坏了，才会现身

哲学家**海德格尔**有一个很有意思的观察。

你用锤子钉钉子的时候，你不会想到锤子，你想的是钉子、是木板。锤子是“**上手**”的，它顺手到**隐形**了。只有当锤头松了、锤子坏了的时候，你才会突然注意到：哦，原来这里有一把锤子。

【配图】一只手握着锤子钉钉子，锤子是半透明的；下一帧锤头松脱，锤子突然变成实色并被高亮。

对人来说，好的界面也是这样，顺手到你感觉不到它的存在。

可对 AI 来说，情况正好反过来。命令行成功的时候，它往往沉默；**出错的时候，它才开口说话**。那一行行报错信息，恰恰是 Agent 的眼睛。它就是靠着“工具出问题时的那一声抱怨”，一轮一轮地修正自己。

所以你看，这是一个很有意思的循环。当年乔布斯和比尔·盖茨费了那么大劲，推广窗口界面，就是为了让电脑更方便人用，越来越傻瓜化。但在 AI 时代，我们又回到了那个经典、优雅、简洁、强大的命令行。

也许再过几年，会出现这样一种可能：**只有 AI 还在直接用电脑，人类不再直接用电脑了，人类通过 AI 来用电脑。** 我们只需要说话。

### 八、查族谱

- 命令行和 Unix：1969 年；
- 管道：1964 年的备忘录，1973 年实现；
- 新的地方：坐在终端前面的，换成了一个 AI。

东西都是老的，用的人是新的。所以这一集的标签是：**重新组合**。

## 内行彩蛋

- **stdin / stdout / stderr**：Unix 程序默认有三条“水管”：标准输入、标准输出、标准错误。把错误单独放一条管，是为了让报错不混进正常数据里。对 Agent 来说，stderr 往往就是最重要的信号。
- **退出码**：每个命令结束时都会返回一个数字，0 表示成功，非 0 表示失败。Agent 判断一步有没有做成，很多时候看的就是这个数字。
- **Rule of Silence**：Eric Raymond 在《Unix 编程艺术》里总结的 Unix 哲学之一：“当程序没什么可说的时候，就什么都不要说。”
- **Computer Use**：2024 年 10 月，Anthropic 发布了让模型通过截图 + 鼠标键盘操作电脑的能力，之后各家都推出了类似的“电脑操作”Agent。
