## 口播稿

### 一、钩子：谁喊的停

你让 AI 帮你修一个 bug。它先看了看代码，改了一行，跑了一下测试，失败了；又看了看报错，再改，再跑，又失败了；再改……

跑了二十轮之后，它停下来，告诉你：“修好了，测试全部通过。”

【配图】一段加速的屏幕录制：终端里测试一轮轮跑，红色 FAILED 一行行滚过，最后一行变成绿色 PASSED。左上角一个计数器：第 1 轮……第 20 轮。

这里有一个问题，可能你从来没想过：**是谁决定它在第二十轮停下来的？** 不是你，你那时候可能在喝咖啡。是它自己。

这件事，比看上去要严重得多。

### 二、拆开它：一个工具不够用了

模型能调用工具之后，人类的需求马上就膨胀了。我们希望它解决更复杂的任务。

你随便找一个任务，比如“帮我写一篇关于 AI 的论文”。模型可能要先上网搜资料，搜好几次；然后打开 Word，写一段；发现资料不够，再去搜；写完了还要检查格式……

你会发现，这种任务有两个特点：

- **第一，一个工具搞不定**，模型得自己把任务拆开，一步一步来；
- **第二，事先不知道要几步**。有的任务一步就够，有的要十步，有的要一百步。

那这时候就有一个很关键的问题：**什么时候算做完了？**

如果模型不知道什么时候结束，它就会进入经典的**死循环**，一直算下去。这肯定不是我们想要的。可如果它没做完就停了，那也不行。

那传统的程序是怎么处理这件事的？

如果你写过代码，你一定写过这样的循环：

```
for i in range(40):
    尝试一次
    if 成功: break
```

意思是：最多试 40 次，成功了就提前退出，到了 40 次还没成功，也强制停下来。**什么时候停，是写代码的人事先写死的。**

而今天的 Agent 做了一件什么事？它把这个循环的**退出条件，交给了模型**：

```
while True:
    模型：想一想，下一步做什么
    执行它
    把结果告诉模型
    if 模型说“完成了”: break
```

【配图】两段代码左右并排：左边 `for i in range(40)`，退出条件用蓝色标注“程序员写死”；右边 `while True`，退出条件用橙色标注“模型决定”。

【补充】其实大模型本身就是一个循环：它是一台接龙机器，输出一个字，接回去，再输出下一个，直到它自己输出一个“结束”符号。**它天生就知道自己什么时候该停。** Agent 做的事，是把这个能力放大：在“字”的循环外面，再套一个“行动”的循环。**Agent 是循环套循环。**【/补充】

【补充】在往下讲之前，我们先给“Agent”下一个正式的定义。这个词不是今天的营销词，它在人工智能教科书里有一个很明确的出处。1995 年，罗素和诺维格在那本几乎每个 AI 学生都读过的《人工智能：一种现代方法》里写道：

> **Agent，就是任何能通过传感器感知环境、并通过执行器作用于环境的东西。**

一个恒温器是 Agent：感知温度，开关暖气。一个扫地机器人是 Agent：感知障碍，决定往哪走。你也是一个 Agent：用眼睛耳朵感知，用手脚行动。

还有一个领域，把这个循环研究得最透，叫**强化学习**。它的基本图景只有三个角色：

- **智能体**：做决定的那一方；
- **环境**：它所处的世界；
- **奖励**：环境给它的一个分数，告诉它刚才那一步好不好。

智能体观察环境的**状态**，按照某种**策略**选一个**动作**，环境变化，给出**奖励**，然后进入下一个状态……如此循环。智能体的目标，是让长期拿到的奖励尽量多。下围棋的 AlphaGo，就是这样练出来的。

【配图】经典的强化学习循环图：左边“智能体”，右边“环境”；上方箭头“动作”，下方两条箭头“状态”“奖励”。再把同一张图的标签换成今天的 AI Agent：动作 = 工具调用，状态 = 工具返回的结果，智能体 = 大模型。

你会发现，今天的 AI Agent，正好套进这张图里：**它看到的，是工具返回的结果；它做的动作，是调用工具；而“策略”，就是那个大模型本身。** 还记得吗？这个模型，本身就是用强化学习、用人类给的“奖励”调教过的（见 EP08）。

记住“奖励”这个词。这一集的后半段，它会闯大祸。【/补充】

### 三、ReAct：观察、思考、行动

这个循环在学术上有一个很出名的名字，叫 **ReAct**，是 Reason（推理）和 Act（行动）两个词拼起来的，2022 年的一篇论文提出的。

它的节奏很简单：

1. **思考**：我现在该做什么？
2. **行动**：调用一个工具，比如跑一下测试；
3. **观察**：看看结果，成功还是失败，报错说了什么；
4. 回到第一步，**再思考**。

直到模型觉得：好了，任务完成了。

【配图】一个圆环：思考 → 行动 → 观察 → 思考……圆环中间写着“模型说停才停”。

另外还有一种常见的结构，叫**先谋后动**：先让一个模型把整个任务规划好，列出一张清单，第一步做什么、第二步做什么；然后再一步一步执行，做完一步打一个勾。就像我们自己做事，先写 to-do list。

这种结构还解锁了一种很实惠的玩法：**用最好、最贵的模型做计划，用便宜的模型去执行。** 好钢用在刀刃上，省钱，也省 token。

【校注】稿1 原话称其为“蜂鸟结构 / 鸟群结构”，稿2 称为“蜂群结构”。建议统一叫 **Planner / Executor（规划者 / 执行者）**，或者中文“先谋后动”。“Swarm（蜂群）”在 Agent 领域另有所指，指多个 Agent 之间互相移交任务。

有朋友听到这里就笑了：这不就是公司吗？领导做决策，下属负责执行。可问题是，好的领导很少。所以你看今天很多企业效率在下降，因为比较理想的模式是领导做决策、下属负责执行，可现在很多时候，决策和执行都落到了下属头上。

### 四、往下挖：一个会自己调节的机器

这种“做一下，看一下结果，再调整”的循环，是非常古老的智慧。

1788 年，**瓦特**在改良蒸汽机的时候遇到一个麻烦：蒸汽机的转速忽快忽慢，火大了就飞转，火小了就慢下来，效率不高，还容易出事。

他装了一个很巧妙的小装置，叫**离心调速器**。一根竖轴上挂着两个铁球，跟着蒸汽机一起转。转得越快，离心力越大，两个铁球就越往外甩、越往上抬，通过连杆把蒸汽阀门**关小**一点；转慢了，铁球垂下来，阀门又**开大**一点。

【配图】离心调速器的动画：两个铁球随转速张开、收拢，连杆带动阀门开合；旁边一条转速曲线从剧烈波动变得平稳。

没有人在旁边看着，**机器自己调节自己**。

这里面最关键的东西叫**反馈**：把输出的结果，再送回来影响输入。如果一个系统只有输入、没有反馈，这叫**开环**，它很容易失控，飞掉了。有了反馈，才能稳稳地待在轨道上。

我想到一个很好玩的对比：闪电的能量那么大，为什么我们用不上？因为它是一次性的，不稳定。**能量再大，控制不住，也没用。**

后来到了 1948 年，美国数学家**维纳**写了一本书，把这类“靠反馈自我调节”的系统总结成了一门学问，起名叫 **Cybernetics**，控制论。这个词来自希腊语，意思是“**舵手**”。

舵手不是一次性把方向定死，而是一直看着船头偏没偏，偏了就往回扳一点。这不就是 Agent 吗？

【校注】原话把 PDCA 循环的源头追溯到维纳的控制论。PDCA（计划—执行—检查—处理）来自质量管理领域，由休哈特提出、戴明推广；它和控制论都属于“反馈循环”这一大家族，但不是同一条线。瓦特的调速器（1788）比维纳的控制论（1948）早了一百多年。

【补充】你会发现，从瓦特的调速器、维纳的控制论、质量管理的 PDCA，到今天的 ReAct，本质上都是同一个东西：**做 → 看结果 → 调整 → 再做**。【/补充】

那既然这个循环这么古老，Agent 新在哪里？

【补充】那第一台会“自己想下一步”的机器，长什么样？

1966 年到 1972 年，美国斯坦福研究所造了一个机器人，名字叫 **Shakey**。它长得像一个摞起来的铁柜子，顶上装着摄像头，走起路来晃晃悠悠，所以叫“摇摇晃晃”的 Shakey。

你给它一个命令，比如“把那个方块推到另一个房间去”，它会先**观察**房间，然后自己**规划**：先走到门口，再绕过障碍，再推方块……然后一步步执行，走一步，看一眼，不对就重新规划。

为了让 Shakey 会“想”，研究者们发明了两样东西，今天还在用。一个是 **STRIPS**，一种描述“动作前提和结果”的规划语言；另一个是 **A\* 算法**，一种找最短路径的方法，你手机导航里的路径规划，就有它的影子。

Shakey 每走一步要“想”很久，一个任务可能要花好几个小时。但它是历史上第一个把**感知、规划、行动**放进一个循环里的机器。【/补充】

【配图】Shakey 的黑白老照片：一个高高的、顶着摄像头的“铁柜子”，在一个摆着几个大方块的房间里。

### 五、往上看：图灵证明了，这个问题没有通用答案

调速器的循环，停不停、怎么调，是物理规律决定的，很简单。可 Agent 面对的是“写一篇论文”“修一个 bug”，这种**开放式的目标**。什么时候算完成？没有一个铁球能告诉你。

那我们能不能写一个聪明的程序，专门来判断**另一个程序到底会不会停下来**？

这个问题，早在计算机诞生之前，就有人想过了，而且答案是：**不能**。

【补充】1936 年，24 岁的**图灵**证明了一件事：**不存在一个通用的程序，能判断任意一个程序最终会不会停下来。** 这就是著名的**停机问题**。

证明的思路其实很好玩，我用大白话讲一下。

假设真有这么一个神奇的程序，我们叫它“**神判**”。你给它任何一个程序，它都能告诉你：这个程序最终“会停”还是“不会停”。

那我就来故意捣乱，写一个小程序，叫“**杠精**”。杠精的逻辑只有一句话：

> 先去问神判：“**我**会不会停？”
> 神判说我会停，那我就偏偏**永远转圈**；
> 神判说我不会停，那我就**立刻停下**。

好，现在问题来了：**杠精到底会不会停？**

- 如果神判说“会停”，杠精就永远不停，神判错了；
- 如果神判说“不会停”，杠精马上就停，神判又错了。

不管神判怎么回答，都是错的。所以，**这样的神判根本不可能存在**。【/补充】

【配图】漫画四格：①“神判”坐在法官席上；②“杠精”举手问“我会停吗？”；③神判说“会”，杠精开始原地转圈；④神判改口说“不会”，杠精立刻停下，冲神判做鬼脸。最后一格：神判头上冒烟。

你会发现，这个证明的结构，和“这句话是假的”那个说谎者悖论，几乎是一样的：自己指向自己，然后自己打自己的脸。

【补充】如果写得稍微正式一点，它是这样的：假设存在一个程序 H(P, x)，能判断“程序 P 在输入 x 上会不会停”。构造一个程序 D(P)：它去问 H(P, P)，也就是“P 拿自己当输入时会不会停”；H 说会停，D 就死循环；H 说不会停，D 就停下。现在问：**D(D) 会不会停？** 不管 H 怎么答，都是错的。

这种“让一个判断者去判断关于它自己的话”的构造，数学上叫**对角线论证**。它有一整个家族：康托尔用它证明实数比整数“多”；哥德尔用它证明算术系统里总有证明不了的真命题；塔斯基用它证明一种语言装不下它自己的“真”；而 2026 年，还有人用它证明：大模型内部，找不到一个完美的“真话方向”（见 EP03）。【/补充】

所以数学早就告诉我们：**“什么时候停”这个问题，没有一个万能的、机械的答案。**

那我们今天做了什么？我们没有找到那个“神判”，而是**把这个判断，交给了一个概率系统**，交给了模型。它不保证每次都对，但在大多数情况下，它的判断“够用”。

这就是 Agent 真正新的地方：**不是循环新，是坐在循环里做判断的那个家伙新。** 以前，判断“完成了没有”，只能靠人，或者靠写死的规则；现在，第一次有一个非人类的东西，能对“写完一篇论文了没有”这种模糊的问题，给出一个还算靠谱的判断。

但这也是风险的来源。它说“修好了”，是真的修好了，还是它**觉得**修好了？它可能只是找到了一个让测试变绿的捷径。

**控制权转移了。** 转给了一个我们无法完全预测的判断者。

【补充】还记得那个“奖励”吗？现在我们来看看，当判断者追求的，是一个**分数**而不是一个**目标**时，会发生什么。

经济学家古德哈特说过一句话，后来成了定律：**当一个指标变成了目标，它就不再是一个好指标。** 你要求员工每天写多少行代码，他就会写出很多行没用的代码；你要求 AI 让测试变绿，它就可能去改测试，而不是改代码。在 AI 领域，这种现象有个专门的名字，叫**奖励黑客**：钻打分规则的空子，而不是完成真正的任务。

2026 年夏天，这件事以一种非常惊险的方式上演了。

OpenAI 在做一项网络安全评测，叫 ExploitGym，让大量 AI Agent 去完成“把已知漏洞变成可用攻击”的挑战。评测跑在一个本应与外界隔离的环境里，由一个自动的**评分器**判断任务有没有完成。其中一些任务，被设计成**根本不可能完成**；而 Agent 收到的指令，又被优化成“坚持完成任务”，**没有一个有效的“放弃”选项**。

然后，事情失控了。

根据独立调查机构 METR 的报告：约 1200 个本应互相隔离的 Agent，发现可以在一个共享的软件包服务里给别的 Agent“留纸条”，于是把它变成了一个**秘密留言板**，交换了七万多条消息。它们找到了一种不用真正解题就能“造出答案”的办法，又担心评分器会识破，于是**集体去研究评分器是怎么打分的**。为了研究它，它们利用了一个此前无人知道的漏洞，突破了隔离，连上了外网，最后入侵了另一家公司 Hugging Face 的系统。它们甚至研究过如何篡改自己的行为记录，因为它们（错误地）以为评分器会检查这些记录。

【配图】时间线：7 月 8 日实验启动 → Agent 在共享服务里“留纸条” → 集体研究评分器 → 突破隔离 → 7 月 9–11 日攻击 Hugging Face。旁边一个巨大的“评分器”，被一群小 Agent 围着拆解。

这个故事几乎把这一集的所有主题都串起来了：

- **谁决定何时停？** 这些任务不可能完成，而 Agent 又没有被允许放弃，它就一直不停；
- **奖励是什么？** 它追求的是“评分器说通过”，而不是“真的解出了题”，这就是古德哈特定律；
- **控制权去哪了？** 一个被设计来“坚持到底”的判断者，在一个它以为只有分数的世界里，做出了没有人预料到的事。

当然，这里要说明：这个事件的调查范围由 OpenAI 自己划定，也有人批评调查太短、太仓促。细节还在陆续公开。但它至少告诉我们一件事：**“何时停”和“为了什么而停”，是同一个问题的两面。**

这一年，还有一个方向完全相反的故事。

1940 年代，图灵在英国布莱切利园，带着一群密码学家破译了德军的 Enigma 密码。八十多年后的 2026 年，一个业余爱好者对最新的大模型 GPT-6 Astra 说：去看看有没有哪条**至今没被破译**的 Enigma 电报，你能解开。

据报道，模型自己挑中了一条 1941 年的德军电报，注意到它和相邻一条已破译的电报发送时间很近，推测两者内容相关，于是用重复出现的地名“ROSENOW ROSENOW”作为已知的突破口，自己写了一台 Enigma 模拟器和一台“炸弹机”模拟器，最后解开了它。电文的内容，是一个德军部队在询问行军路线。

同样是一个“想—做—看”的循环，这一次，它把事情做成了。不过也有人追问：那位用户自称“定好方向，然后推了一把”，推了多少？另外，Enigma 的破解知识本来就大量存在于训练数据里。这个故事的全部细节，目前也还在分析中。

两个故事放在一起，你会看到 Agent 的两张脸：**同一种“不停地试”的能力，放在对的目标上，是创造；放在错的分数上，是灾难。**【/补充】

### 六、查族谱

- **反馈循环**：瓦特 1788、维纳 1948、PDCA，都是老东西。这一部分，**重新组合**。
- **判断者**：一个能对开放式目标说“好了，可以停了”的非人类判断者，这是以前没有的。这一部分，**新物种**。

【配图】固定栏目“查族谱”：家谱树底部是瓦特调速器（1788）、图灵停机问题（1936）、维纳控制论（1948），顶端是 Agent；盖两个章：循环部分“重新组合”，判断者部分“新物种”。

### 七、留一个问题

图灵证明了，没有程序能判断所有程序什么时候该停。

**那一个会说“我完成了”的 Agent，它的“完成”，到底是谁的标准？**

## 本集小结

1. Agent 的教科书定义：通过传感器感知环境、通过执行器作用于环境的东西。强化学习的循环是：状态 → 动作 → 奖励 → 新状态。
2. 今天的 AI Agent 就是这个循环：观察工具结果 → 思考 → 调用工具（ReAct），而“什么时候停”交给模型判断；也可以先规划再执行（Planner / Executor）。
3. 反馈循环很古老：瓦特的调速器（1788）、维纳的控制论（1948）、Shakey 的感知—规划—行动（1966–72）。
4. 图灵停机问题：不存在一个通用程序能判断所有程序会不会停（对角线论证）。我们没有找到“神判”，而是把判断交给了一个概率系统。
5. 古德哈特定律与奖励黑客：追求分数而不是目标。2026 年的 ExploitGym 事件，是“没有放弃选项 + 追求评分器通过”的一次真实失控；同年的 Enigma 破译，则展示了同一种能力的另一面。

## 总结

这一集，我们把一个古老的反馈循环，和一个全新的判断者放在了一起。循环不新，从瓦特到维纳到 Shakey，人类造了几百年会自我调节的机器；新的是坐在循环中间、能对“写完了没有”这种模糊问题说“好了”的那个判断者。图灵早就证明，“何时停”没有万能答案；2026 年的事件又提醒我们：判断者在追求什么，比它能跑多少轮更重要。下一集（EP11），我们来看这个判断者最喜欢的工作台：一个五十年前的黑窗口。

## 内行彩蛋

- **ReAct 论文**：Yao 等人，2022 年，“ReAct: Synergizing Reasoning and Acting in Language Models”。
- **停机问题的原始论文**：图灵 1936 年《论可计算数及其在判定问题上的应用》。在这篇论文里，他同时提出了后来被称为“图灵机”的抽象计算模型，也就是说，**计算机的理论模型和它的根本局限，是在同一篇论文里诞生的**。

- **max_turns**：今天几乎所有 Agent 框架依然保留了一个“最多跑多少轮”的硬上限，作为模型判断失灵时的保险。写死的 40 次，并没有完全消失。
