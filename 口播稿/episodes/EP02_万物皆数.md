## 口播稿

### 一、钩子：它为什么数不清草莓里有几个 r

你问大模型“草莓是什么颜色的”，它会告诉你红色。当然草莓也有别的颜色，但它大概率告诉你红色，这很正常。

但如果你问它：**strawberry 这个单词里，有几个字母 r？**

很长一段时间里，很多模型都会答错。它会很自信地告诉你：两个。

【校注】原话说“strawberry 里有 2 个 r”，其实是 **3 个**：st**r**awbe**rr**y。有意思的是，“答 2 个”恰恰是当年模型最经典的错误答案，所以口播里可以顺势说成“它会告诉你两个，其实是三个”。

【配图】大字 strawberry，三个 r 依次高亮；旁边一个聊天框截图，模型回答“There are 2 r's”。

如果换成中文，就好比你问它：“**森林**”这两个字里，一共有几个“木”？人一看就知道，森是三个木，林是两个木，一共五个。但模型可能就数不对。

为什么？一个能写论文、能写代码的东西，怎么会连字母都数不清？

这个问题问得很好。它涉及大模型到底是怎么“看”语言的。

### 二、拆开它：模型看到的，根本不是字

我们人看到的是字形，是符号。中文的话，我们看到偏旁部首；英文的话，我们看到 26 个字母。

模型看到的也是符号，但**它的符号和我们的不是一种东西**。

计算机只认识数字，说到底就是 0 和 1。它不可能直接理解“我是中国人”这几个汉字是什么意思。那怎么办？我们得先把字变成数字。

最简单的想法是这样的：给每个字编个号。“我”是 1，“是”是 2，“中”是 3，“国”是 4，“人”是 5。这样“我是中国人”就变成了 1、2、3、4、5，完成了从自然语言到数字的一次翻译。

【配图】动画：“我 是 中 国 人”五个字依次落进五个格子，格子下面弹出 1 2 3 4 5。

今天大模型里真正的做法，比这个稍微复杂一点，但思路是一样的，这就是所谓的 **Token**。

**Token 既不是字，也不是词**，它是模型词表里的一个“小块”。strawberry 这个词，在模型眼里可能不是 10 个字母，而是被切成了几块。

【补充】具体怎么切，每个模型不一样。比如在某个常见模型的词表里，strawberry 会被切成 `str`、`aw`、`berry` 三块。每一块在词表里有一个编号，比如 `str` 是 496，`aw` 是 675，`berry` 是 15717（编号只是举例）。【/补充】

【校注】原话的切分是“straw、berry、der，再加上 y”，不准确。改为一个示意性的切分，并注明各家模型切法不同。

【配图】strawberry 被剪刀剪成三块彩色积木 `str | aw | berry`，每块下面挂一个编号牌。

然后第二步，这个编号还会再被换成一组浮点数，也就是一个**向量**。比如 496 号对应一串几千个数字，15717 号对应另一串。所以最终，模型看到的 strawberry，可能就是**三个向量**。

那你想想，一个向量怎么可能知道里面有几个 r？字母这个信息，在切块的那一刻，就已经被“打包”进去了。模型根本没有“看到”过 r。

这就好比有人把“森林”两个字，直接换成一个编号“8848”递给你，然后问你：这里面有几个木？你上哪儿数去？

所以说到底，这不是模型笨，而是**它看世界的方式和我们不一样**。

【补充】顺便说一下整个流程。你输入一句话，它先被切成 token，变成编号，再变成向量，送进模型。模型算完之后，输出的其实不是一个字，而是**整个词表上的一张概率表**：下一个 token 是这个的概率多少，是那个的概率多少。然后从中抽一个，再把编号翻译回文字给你看。

所以你会发现，这是一个**翻译进去、再翻译出来**的过程。人的语言翻译成机器的数，机器的数再翻译回人的语言。【/补充】

【校注】稿2 原话：“将自然语言变成向量叫 Encoding，将向量转成自然语言叫 Decode；模型输出一串向量，再查词表找到词。”两处调整：（1）模型输出的是词表上的概率分布，不是“一个向量再去查表”；（2）Encoder / Decoder 在 Transformer 里另有所指，这里改说“翻译进去 / 翻译出来”，避免和后面讲注意力时混淆。

【配图】流程动画：文字 → 剪成 token → 编号 → 向量（一串数字）→ 黑盒模型 → 概率柱状图 → 抽中一个编号 → 翻译回文字。左边标“人的语言”，右边标“机器的数”。

那为什么今天的模型又能答对了呢？大概有两个原因。

第一个是**思维链**。今天很多模型在回答之前，会先在“脑子里”多想几轮，就像人说的三思而后行。它会先写下草稿：strawberry，s-t-r-a-w-b-e-r-r-y，一个字母一个字母拆开，然后再数。你会发现，它其实是**绕过了自己的 token**，把一个词重新拆成一个个字母，变成它能数的形式。

第二个原因，我猜多半是专门针对这类问题做了训练，毕竟它太出名了。就像是一个骑自行的鹈鹕，原本只是一个玩笑，现在变成了每个模型的通用测试案例，自然而然，所有模型都要对这个案例专门优化。

### 三、往下挖：万物皆数

好，模型看不到字，只看到数。那问题来了：**世界上的东西，真的都能变成数吗？**

这个想法最早的源头，可以追溯到两千五百多年前的古希腊，**毕达哥拉斯**学派。

据说毕达哥拉斯发现了一件很神奇的事：拿一根琴弦，弹出一个音。你把弦长减半，音就高了八度；弦长变成三分之二，就是一个非常和谐的五度音；变成四分之三，是四度。**只要用简单的整数比例，就能把好听的音程找出来。**

【校注】原话说“只要用适当的比例，就可以变成五阶、四阶、七阶”，这里说的应该是“八度、五度、四度”这几个和谐音程，对应弦长比 1:2、2:3、3:4。

【配图】一根琴弦，下面标出 1/2、2/3、3/4 的位置，配上对应的音；可以直接拍一段吉他或古琴按弦的实拍。

他觉得这简直妙不可言。同时他们还发现了勾股定理，就是我们今天说的毕达哥拉斯定理：a² + b² = c²。几何也可以用数来表达。

于是他们得出一个非常大胆的结论：**万物皆数**。世界的本质就是数，数与数之间的关系，就是世界的规律。

然后到了十七世纪，德国有一个大神叫**莱布尼茨**，他做了更进一步的简化。他觉得世界不需要那么复杂的十进制，**只用 0 和 1，就可以表达所有的数**。这就是二进制。

莱布尼茨是一个很虔诚的宗教信徒。在他看来，1 代表上帝，0 代表虚空，上帝从虚无中创造了万物，就像 1 和 0 可以组合出所有的数。据说这也是他痴迷二进制的一个重要原因。

那这里有一个中国观众特别感兴趣的故事。莱布尼茨研究二进制的时候，一个在中国传教的法国传教士**白晋**，给他寄去了伏羲六十四卦的图。莱布尼茨一看就震惊了：阳爻是一，阴爻是零，六十四卦从坤到乾，正好就是从 0 到 63 的二进制！

【配图】伏羲六十四卦方圆图（白晋寄给莱布尼茨的那一版）；旁边把几个卦象逐一翻译成二进制，比如坤 = 000000，乾 = 111111。

但是这里要澄清一个很常见的误会：**不是《易经》启发了莱布尼茨发明二进制。** 莱布尼茨早在 1679 年就已经在手稿里研究二进制了，1701 年才收到白晋寄来的卦图，1703 年才正式发表他的二进制论文，并在里面提到了伏羲。所以更准确的说法是：他发明了二进制，然后惊喜地发现，几千年前的中国人好像也“想到过”。

【补充】关于这几个年份：1679 年手稿、1701 年收到卦图、1703 年发表论文《论只用 0 和 1 的二进制算术》。口播中可以只说“早在收到卦图二十多年前”。【/补充】

那既然说到这里，我还想聊一个我自己的理解，也是东西方很有意思的一个差异。

到了 1948 年，计算机史上最重要的人物之一**香农**，提出了信息论，还给了信息一个单位，叫 **bit**，比特。在香农的体系里，一个比特就是一个比特：0 就是 0，1 就是 1，它是确定的，而且每一位**只表达一件事**。你要表达更复杂的信息，那就用更多的比特。8 位不够就用 16 位，但你不应该在一个比特里塞好几层意思，因为那样不利于传递，也不利于理解。

而伏羲的八卦不太一样。同样是阴和阳，一个爻，它既可以代表男女，也可以代表天地，还可以代表刚柔。它的信息密度非常高，一套卦象想要解释整个宇宙，所以它的意义特别庞杂，特别多元。

这不是说谁好谁坏。只是**今天的计算机选择了香农这条路：要精确，一个符号只干一件事。**

【配图】左右对比：左边一个“乾卦”，周围环绕“天、父、刚、健、首、马……”一圈含义；右边一个比特“1”，旁边只写一个“1”。

### 四、往上看：变成数的时候，我们丢掉了什么

所以你会发现，今天的大模型依然是这套逻辑的延续。语言在它这里变成了向量，语言和语言之间的关系也变成了计算。从毕达哥拉斯的“万物皆数”，到莱布尼茨的 0 和 1，到香农的比特，再到今天的 token，**正是因为相信世界可以用数来表达，才有了计算机，才有了今天的大模型**。

但是 strawberry 这个小小的例子也提醒我们：**每一次把世界翻译成数，都会丢掉一些东西。**

模型把 strawberry 打包成三块的时候，它得到了效率，丢掉了字母。人把世界翻译成语言的时候，其实也一样。你说“红色”，就丢掉了草莓表面那一点点光泽、那一粒粒籽。

【配图】一颗真实草莓的特写 → 变成“红色”两个字 → 变成一个编号 → 变成一串数字。每一步画面都更抽象，颜色一点点褪掉。

### 五、查族谱

Token 这个东西，查一查族谱：

- 把文字变成数字，电报时代就开始了，后来有 ASCII，有 Unicode；
- 把高频片段合并成一个“块”，这个思路来自 1994 年的一种**压缩算法**，叫 BPE，本来是用来压缩文件的，2016 年前后被搬到了机器翻译里；
- 用 0 和 1 表达一切，那是莱布尼茨和香农的遗产。

所以 token 本身没有什么新东西，它是**重新组合**。

【配图】固定栏目“查族谱”：家谱树底部是毕达哥拉斯、莱布尼茨（1703）、香农（1948）、BPE 压缩算法（1994），顶端是 Token；盖章“重新组合”。

## 内行彩蛋

- **中文的 token 效率**：同样一句话，中文和英文消耗的 token 数量不一样。早期的一些词表里，一个汉字常常要一到两个 token，这意味着中文用户“同样的钱，说的话更少”。新一代模型的词表对中文友好了很多。
- **BPE 的出身**：Philip Gage 1994 年发表的是一种数据压缩算法；Sennrich 等人 2016 年把它用到神经机器翻译里，解决生僻词问题。今天大部分大模型的分词都是它的后代。
- **希帕索斯的传说**：毕达哥拉斯学派相信一切都是整数之比，据说有个学生发现正方形的对角线（√2）无法写成整数比，结果被扔进了海里。“万物皆数”的第一次危机。（传说，未必真实）
