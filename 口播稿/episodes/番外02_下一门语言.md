## 口播稿

### 一、钩子：你说人话，它去干活

【补充】你对 AI 说：「帮我把这份口播稿，按每集一个文件拆开，事实错误标出来。」它就去干活了。

没有函数名，没有分号，没有先声明变量。你说的是人话。

那我问你一句，今天很多人已经问过的：

> **Prompt，是不是一种新的编程语言？**

要回答它，得先问另一个更老的问题：人类为什么要不停地发明新语言？机器明明越来越强了，人却一次次觉得，直接跟它说话，太累。【/补充】

### 二、拆开它：一把往人这边搬的梯子

【补充】计算机只认一种话：一串 0 和 1，按它此刻的电路，刚好是某条指令。这叫**机器码**。人要是直接写这个，等于拿着显微镜数沙子。

于是有了**汇编**：把 `10110000` 这种东西，写成 `MOV`。人好记一点，可你还是在跟这台机器的零件说话，换一颗芯片，助记符可能就得换。

再往上，人受不了了。科学家想算公式，不想管哪条寄存器腾得出手。1950 年代出现了 **FORTRAN**，公式翻译：你写接近数学的式子，由编译器把它翻译成机器码。这是梯子上我们要停下来讲的那一级，稍后展开。

再往后，**C** 让你离机器近一点，但别那么近，好写操作系统；**Java** 让你离某一台具体的机器再远一点，「写一次，到处跑」；**Python** 让你看起来像在写英语，少写很多仪式。

你可以把它看成一把梯子：

```
机器码 → 汇编 → FORTRAN → C → Java → Python → Prompt / Skill
```

每一级，都是人把「怎么说」往自己这边搬了一点。机器并没有变懒，是人发现：直接跟铁说话，太累。机器越强，人越不想为它的细节买单。你看这个方向其实挺吊诡的：硬件一代代更快，人写的字却一代代更像人话。快出来的余量，被拿去买「我不用记那么多规矩」。

Python 后来又往回摆，加上类型、加上越来越像 Java 的结构——这件事正片 EP14 讲过，这里不重讲。你只要记住钟摆：太松了要往右，太死了又有人往左。【/补充】

【配图】一把竖着的梯子，每一级亮一下，旁边一句人话：「数沙子」→「记助记符」→「写公式」→「管内存」→「到处跑」→「像英语」→「就是英语？」。

### 三、往下挖：让公式自己变成铁

【补充】1954 年到 1957 年，IBM 的**约翰·巴克斯**带了一小队人，做一件当时很多人都觉得不靠谱的事：让计算机自己把公式翻成指令。产品后来叫 **FORTRAN**，Formula Translation。

那时候写程序，主流还是汇编。有人觉得，高级语言写出来的东西，一定又慢又胖，正式的活还得手写机器码。FORTRAN 的编译器偏要证明：翻译过去的指令，可以快到让你愿意扔掉汇编。它做到了。科学计算从此可以用接近数学的语言说话。

梯子上这一级的意义，不是「又多了一种语法」。而是第一次把一项分工说死：**人用接近问题的语言写，机器负责翻译成铁能执行的语言。** 翻译必须靠得住——同一段公式，今天编译、明天编译，出来的指令可以不同，算术结果不能不同。这是后来所有「高级语言」暗暗遵守的契约。Prompt 后来恰恰是在这块契约上打了折扣。

这分工其实更早就有人在喊。美国海军的**格蕾丝·霍珀**，在 1940 年代末、50 年代初就主张：机器该来迁就人类的语言，而不是反过来。她参与过编译器的早期工作，后来那句流传很广的话，大意是——别人说做不到的时候，你更要去做。FORTRAN 不是她的作品，但「让人用自己的话写，让机器去翻译」这件事，她是最早较真的人之一。

【校注】霍珀常被说成「编译器之母」。更准确的说法：她在 UNIVAC 上做了 A-0 等早期编译系统，并大力推动接近英语的语言（后来的 COBOL 受她影响很深）。FORTRAN 是巴克斯团队的产品。口播里把「分工」归于这个传统，把历史节点留给 FORTRAN，避免把两个人焊成一个人。

C、Java、Python，在这把梯子上只是路标。每一级都在重复 FORTRAN 证明过的那件事：人可以离铁远一点，只要中间那层翻译靠得住。【/补充】

【配图】1950 年代的机房，一份写着公式的纸 → 一台编译器齿轮 → 一排打孔卡片变成指令。旁白字幕：「人写公式，铁去跑」。

### 四、往上看：Prompt 像语言，又不像

【补充】按霍珀的方向看，Prompt 简直像下一格：人用自己每天说的话写，模型去翻译成调用、命令、代码。

可它缺了 FORTRAN 最硬的那一块。

同一句 Prompt，跑两次，可能给你两段不一样的代码。你让它「写一个把口播稿按集拆开的脚本」，上午它用正则，下午它用标题匹配，两次都能跑，两次都不一样。它没有一份稳定的语法说明书，说「这样写，机器必须这样理解」。真正去执行、去保证 3 + 5 一定等于 8 的，仍然是 Python、JSON、系统调用，那些确定性的零件。编译器不会「猜你的意思」；模型会，这也是它能干活、也会把 60 分涂成绿色的原因。

所以更老实的说法也许是：Prompt 不像 FORTRAN，它更像一份**规格说明书**，后面跟着一个**会读模糊的解释器**。说明书可以写得松；解释器会补，也会乱补——60 分显示成绿色，就是乱补（见 EP14）。

戴克斯特拉当年骂「自然语言编程」愚蠢，正片已经请他出过场。本集不请他再骂一遍。只记住他的担心：模糊一旦进了语言，确定性就很难回来。Skill 越写越像伪代码，钟摆往右，其实就是在回应这个担心。

那为什么还不把 Prompt 直接扔掉、全写成 Python？因为 AI 带来了一些代码以前不太会的东西。正片列过五条，这里再用一遍：

1. 对自然语言需求的理解；
2. 对未知情况的适应；
3. 对 corner case 的自主修复；
4. 一次性、个性化需求的低成本处理；
5. 不需要工程师为每一个变化修改程序。

这五条，没有一条要求你取消代码。它们要求代码旁边，站一个能读「大概」的东西。

所以终局不是「Prompt 取代 Python」，更不是「AI 替代代码」。而是：

> **确定性的代码，加上非确定性的模型，开始共同组成新的软件。**

人话进，铁上跑。中间那层翻译，这一次不再是编译器那种一一对应，而是一个会猜、会补、会改主意的模型。这是新的；底下的代码、协议、命令行，仍是旧的。【/补充】

## 本集小结

1. 人类不断发明新语言，是因为直接跟机器说话太累。梯子：机器码 → 汇编 → FORTRAN → C → Java → Python → Prompt / Skill。
2. FORTRAN / 编译器（巴克斯，1957）把分工说死：人用接近问题的语言写，机器翻译成铁能执行的语言。霍珀更早主张机器迁就人类的话。
3. Prompt 没有稳定语法，同一句两次可以不同；真正执行的仍是代码。它更像规格说明书 + 会读模糊的解释器。
4. AI 带来代码不太会的五件事（与 EP14 同一清单）。终局不是 Prompt 取代 Python，而是确定性的代码 + 非确定性的模型，组成新软件。
5. 查族谱：梯子重新组合；读人话的解释器是新物种候选。

## 总结

正片讲 Skill 的时候，已经撞上了「为什么不直接写成 Python」。这一集把那一撞，放到七十年的梯子上看。人一次次把语言往自己这边搬，是因为铁太硬；每一次搬成功，都靠中间那层翻译靠得住。Prompt 像下一格，又缺最硬的那一块。所以它大概不是 FORTRAN 的亲戚，而是一份松的说明书，后面跟着一个会猜的解释器。新软件不是把代码请走，是让代码和模型坐在一张桌子上。季终（EP16）会把这张桌子，放回两条河之间。
