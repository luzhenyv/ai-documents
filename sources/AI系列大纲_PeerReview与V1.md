# AI 外壳下的技术史与技术哲学 —— Peer Review 与重设计 V1

> 本文分三部分：一、对原始草稿与 ChatGPT 讨论的 peer review；二、重新设计的系列大纲；三、需要你拍板的问题。
> 大纲仍保持"关键词级"，方便后续迭代。

---

## 第一部分：Peer Review

### 1. 最大的结构问题：母叙事太"大"，大到没有张力

ChatGPT 最后收敛的母叙事是「人类不断寻找一种方法，把自己的思想交给机器」。这句话没错，但它的问题恰恰是**什么都能装进去**——毕达哥拉斯、ENIAC、Python、MCP 全都"符合"。一条能解释一切的主线，实际上什么也没解释，也推不动叙事。

故事需要冲突。你的素材里其实藏着一条真正有张力的线，ChatGPT 没有点出来：

> **"写下规则"与"学出规则"之间两千年的拉锯。**

- 规则派（符号主义）：莱布尼茨「让我们来算一算」→ 布尔 → 图灵 → 编程语言 → 专家系统 → 今天的 Skill / Workflow / Script
- 学习派（联结主义）：感知机 → 神经网络 → 深度学习 → LLM
- 今天的 Agent 恰好是两条河**第一次真正汇合**的地方：模型（学出来的）写代码、调工具（写下来的）。你草稿里那句「确定性的代码 + 非确定性的模型」，本质就是这个。

这条线有胜负、有反转（感知机被判死刑、AI 寒冬、GPU 意外救场）、有今天的悬念（Skill 越写越像代码 = 规则派回潮？），而且直接接住你最强的个人观点：Python 越来越像 Java、Skill 越来越像伪代码——这是**钟摆**，不是偶然。

### 2. 第二个结构问题：最终版本丢掉了"AI 外壳"

ChatGPT 最后一版（8 章 + Finale）按历史顺序排：第一章毕达哥拉斯、第二章 ENIAC、第三章编程语言……Tool Calling 拖到第五章、Agent 拖到第七章。

这与你"披着 AI 外壳"的要求相反。零基础观众是冲着 Agent、Skill 这些热词点进来的；第一集讲毕达哥拉斯，流失会很严重。更隐蔽的问题是：它在第五章讲 Tool Calling，第六章才讲"机器怎么学习"——先用 LLM，后解释 LLM，顺序也不自洽。

**原则应该是：按 AI 概念的逻辑顺序排集，历史在每集内部"倒着挖"。** 观众始终站在今天，历史是铲子，不是时间轴。

### 3. 最重要的技术遗漏：「下一个字预测」一次都没出现

整个讨论里没有出现 next-token prediction（自回归生成）。这是理解 LLM 最关键的一个概念，而且它后面每一集都要用：

- Tool Calling 的本质：模型只是"接龙"接出了一段恰好是 JSON 的文字，**执行的永远是外面的程序**；
- 为什么同一个 Skill 两次结果不同：采样、温度；
- 为什么上下文会"越聊越长"：每生成一个字都要重新看一遍前文；
- 你那个"90 分全绿"的 bug：模型在做最省力的续写，而不是在"理解需求"。

草稿中"输出向量 → 查词表 → 找到词"的描述也不准确：模型输出的是**整个词表上的概率分布**，每次抽一个 token，再把它接回输入，循环。这其实就是全系列第一个"循环"，可以给第五集 Agent Loop 埋伏笔：**LLM 本身就是一个循环，Agent 是循环套循环。**

### 4. 事实层面需要修正的地方（专业观众会挑刺）

| 原说法 | 问题 | 建议 |
|---|---|---|
| MCP「就是网络协议」「底层封装 HTTP」「解决跨电脑调用」 | MCP 基于 JSON-RPC 2.0，传输层**既有 stdio（本机进程）也有 HTTP**。大量 MCP Server 就跑在你自己电脑上。它解决的核心不是"远程"，而是 **M 个应用 × N 个工具的集成爆炸**，把 M×N 变成 M+N | 讲成「AI 世界的 LSP / USB 接口」。MCP 官方明确说受 LSP（2016，微软）启发——这本身就是你要的"旧瓶新酒"的铁证 |
| 大模型参数是 32 的倍数是因为 CUDA warp = 32 | 方向对，但只是原因之一。更常见的是 64/128 的倍数，还涉及 Tensor Core 的分块形状、显存对齐、矩阵分块 | 讲成「数字背后有硬件」，别用一个新神话替换旧神话。附一个好例子：Karpathy 把 nanoGPT 词表从 50257 补到 50304（64 的倍数），训练快了约 25% |
| 「Encoding = 文字变向量，Decode = 向量变文字」 | 在 Transformer 语境里 encoder/decoder 另有所指（GPT 是 decoder-only），专业观众会混淆 | 用「tokenizer 的编码/解码」限定范围，或换成"翻译进去 / 翻译出来" |
| Plan-and-Execute 叫「蜂群」（转录里还有「蜂鸟」） | "Swarm" 在 Agent 领域另有所指（多 Agent 互相移交） | 统一叫 Planner / Executor，或「先谋后动」 |
| Claude Code、Codex 用 Node.js 或 Python，所以用异步 | Codex CLI 在 2025 年已用 Rust 重写。而 Rust 版本依然是异步架构——这反而**更有力地证明**异步的原因是 I/O 等待，而非语言 | 保留"延迟尺度"论证，删掉语言归因 |
| 上下文超过 30% 就降质 | 这是经验值，不是定律，不同模型差别很大 | 口播时说"很多人的经验是"，并提 context rot 这个现象 |
| Sub-Agent 像多线程，主要为了并发 | 并发是一个原因，但 Sub-Agent 更核心的价值是**上下文隔离**：让子任务的一堆中间垃圾不污染主 Agent 的上下文 | 这恰好和 Skill 集的"上下文是资源"呼应，是个好转折 |
| 「y = kx + b 和大模型是同样的结构」 | 作为类比很好，但要补一句：大模型是**非线性**的，这正是需要"深"的原因；训练靠梯度下降"下山"，而不是解方程 | 下山比喻零基础也能懂 |
| 「Harness APP」 | 不是通用术语，业内说 agent harness | 顺便讲词源（见下） |

另外，语音转录的错误需要系统清理：帮/把、Scale→Skill、IReact→ReAct、EM→1M、OK flow→Workflow、分装→封装、副 Agent→主 Agent 等。ChatGPT 没有替你标出来，还沿用了"蜂群"。

### 5. 对 ChatGPT 讨论方式本身的提醒

几乎每一轮都以「非常好」「非常漂亮」开头，没有一次反对你的观点。结果就是：你原稿里的 MCP 误述，它先指出、后来又顺着你讲成"访问远程世界"；"32 = warp"它照单全收；集数从 7 → 9 → 10+1 → 8+1 一直在膨胀，没有人在做减法。

还有一个可能的误读：你说「可以考虑一个简单接地气的项目，贯彻始终。就像是 padding，调整一个视频的时长」。我理解你的意思可能是**这个贯穿项目像 padding 一样，用来灵活调节每集时长**；ChatGPT 理解成了"项目内容就是剪视频"。这点需要你确认（见第三部分）。

### 6. 对你自己立场的一点反向提醒

「没有那么多新东西」是这个系列最鲜明的态度，但它有一个风险：**反炒作本身也会变成一种炒作**。如果每集结论都是"不过是旧瓶新酒"，第三集以后观众就能猜到结尾，专业观众也会觉得不公平——Transformer 的规模效应、上下文内学习（in-context learning），当年确实让整个领域都意外了。

建议把态度从「这不新」升级为「**鉴定它到底新在哪一层**」。每集结尾做一个固定环节，给当期主角打一个标签：

- **改名**：同一个东西换了名字（如：多层感知机 → 深度网络的部分营销）
- **重组**：旧零件的新组合（如：MCP = RPC + 服务发现 + 为模型写的说明书）
- **真新**：以前做不到的能力（如：一个能读懂模糊自然语言的"解释器"）

这样你的批判性有了标尺，也更可信。整季的结论也可以落在一句话上：**旧零件，新胶水**——几乎所有零件都是旧的，但那层把它们粘起来的"能读懂人话的胶水"，是真新的。

### 7. ChatGPT 遗漏的、但极其贴合你风格的素材

历史与哲学是你的特色，但讨论里的哲学问题大多停留在"什么是理解""什么是智能"这类泛问。下面这些素材更具体、更有"原来如此"的效果，已放进下面的新大纲：

- **马尔可夫 1913**：统计普希金《叶甫盖尼·奥涅金》前两万个字母的元辅音规律——"下一个字预测"的祖先是一首诗。
- **香农 1948**：用统计近似生成"像英语的乱码"——GPT 的曾祖父。
- **莱布尼茨与《易经》**：莱布尼茨的二进制论文（1703）明确提到伏羲卦象。对中文观众是绝佳钩子。
- **Firth 1957**：「观其伴，知其义」(You shall know a word by the company it keeps) + 维特根斯坦「意义即用法」——这才是 embedding 真正的哲学祖先。
- **塞尔「中文屋」1980**：讨论"机器理解语言"的思想实验，主角恰好是中文。
- **奥斯汀《如何以言行事》**：有些话本身就是行动（"我宣布会议开始"）。Tool Calling 就是让模型说出"施事话语"。
- **维纳《控制论》1948**：Cybernetics 词源是希腊语"舵手"，核心就是反馈回路——Agent Loop 的直系祖先。
- **图灵停机问题 1936**：数学上证明了"程序无法普遍判断另一个程序何时停止"；而今天我们把"何时停"交给了模型。这是你"谁决定任务完成"的最佳历史对照。
- **专家系统（MYCIN、XCON，1970–80 年代）**：知识工程瓶颈导致第二次 AI 寒冬。**Skill 就是知识工程 2.0**。关键问题：这次有什么不同？
- **Polanyi 悖论**：「我们知道的比说得出来的多」——解释规则派为什么失败，也解释 Skill 为什么难写。
- **Sutton《苦涩的教训》2019**：长期看，堆算力的通用方法总会打败人工灌输知识。与 Skill 的回潮构成正面冲突。
- **Sara Hooker《硬件彩票》2020**：思想能不能赢，取决于它是否恰好适配当时的硬件。完美承接你的"32 与 warp"。AlexNet（2012）用两块 GTX 580 游戏显卡训练。
- **Dijkstra EWD667（1978）**：《论"自然语言编程"之愚蠢》。放在 Skill 集，与"Skill 越来越像代码"正面对话。
- **Atlas 计算机 1962 的虚拟内存 / 按需分页**：Skill 的"渐进式披露"几乎就是按需分页的翻版。
- **McIlroy 1964 管道备忘录**：「程序应该像花园水管一样能接起来」。
- **《人月神话》1975**：给延期项目加人只会更延期——沟通成本 n(n-1)/2。直接适用于 Multi-Agent。
- **Harness 词源**：马具。模型是马，Harness 是套在马身上、让马力变成拉车的装置——这个比喻比"操作系统"更直观，也更有画面感。
- **Tesler 定律**：「AI 就是那些还没被做到的事」——一旦做到，就不叫 AI 了。适合当季终的收尾。
- **延迟尺度**：把 1 个 CPU 周期（约 0.3ns）放大成 1 秒，跨大洲网络往返约等于 4 年，一次 30 秒的 LLM 调用约等于 3000 年。

## 第二部分：重新设计的系列大纲 V1

### 系列定位

- **工作标题**：《旧零件，新胶水》（备选：《AI 没那么新》《从算盘到 Agent》）
- **一句话**：用今天最热的 AI 概念作入口，每集向下挖到一个更古老、更稳定的思想，再带着它回来看 AI。
- **母叙事**：「写下规则」与「学出规则」的两千年拉锯，在 Agent 时代第一次汇合。
- **观众承诺**：零基础能听懂主线；专业观众能拿到至少一个"原来是这样"；最差也能带走几个能讲给别人听的故事。

### 每集固定结构（约 15–25 分钟）

1. **钩子**（今天的现象，1–2 分钟）：一个具体、反直觉的问题
2. **拆开它**（零基础主线）：用一个比喻讲清楚它是什么
3. **往下挖**（历史）：一到两个历史节点，讲故事而非讲年表
4. **往上看**（哲学）：一个具体的思想家或思想实验
5. **贯穿项目进度**：本集的概念如何推进那个项目（可伸缩，调节时长）
6. **新旧鉴定**：给本集主角打「改名 / 重组 / 真新」标签
7. **留一个问题**：不给答案

每集另设一条「给内行的彩蛋」，放在画面角标或简介里，实现两层叙事。

### 贯穿项目（建议）：这档节目是怎么做出来的

与其用"把 20 分钟视频剪成 10 分钟"（这个任务需要理解视频内容，其实很难，而且讲不到 embedding、MCP），我建议用一个更真实、也更有元叙事味道的项目：**用 AI 把一段语音日志做成一期节目**——正是你现在在做的事。

语音转录 → 整理文稿 → 生成 slide → 做配图 → 发布到平台。每个环节都天然对应一集：转录错误（"帮/把"）引出 token；调用 Whisper/FFmpeg 引出 Tool Calling；反复修改引出 Agent Loop；你的口播稿工作流本身就是一个 Skill；发布到公众号可以引出 MCP。季终时观众会意识到：**他们看的这一季，本身就是这套系统的产物。**

### 第一幕：它到底是什么（语言机器）

#### EP01｜接龙机器：大模型其实只做一件事

- **钩子**：手机输入法的联想词，和 ChatGPT 是远房亲戚吗？
- **主线**：next-token prediction；概率分布；采样与温度；"大模型本身就是一个循环"
- **往下挖**：马尔可夫 1913（普希金的诗）→ 香农 1948（生成"像英语的乱码"）→ n-gram → GPT
- **哲学**：塞尔「中文屋」——一个只会接龙的东西，能说它"懂"吗？
- **内行彩蛋**：自回归与 KV Cache；为什么越聊越慢、越贵
- **带走的念头**：LLM 是一台"猜下一个字"的机器，后面所有魔法都建立在这件朴素的事上
- **鉴定**：重组（统计语言模型 + 规模）

#### EP02｜词语如何变成数字：意义住在哪里？

- **钩子**：为什么 AI 数不清 strawberry 里有几个 r？
- **主线**：token（不是字也不是词）；token ID；embedding；向量距离；国王 − 男人 + 女人 ≈ 女王
- **往下挖**：毕达哥拉斯「万物皆数」→ 莱布尼茨二进制与《易经》→ 布尔 → 香农的 bit → ASCII/Unicode → Word2Vec
- **哲学**：Firth「观其伴，知其义」+ 维特根斯坦「意义即用法」——意义不在词里，而在词与词的关系里
- **贯穿项目**：语音转录里的"帮/把"错误从何而来
- **内行彩蛋**：中文和英文的 token 效率差异；静态 embedding 与上下文表示的区别
- **带走的念头**：计算机没有"突然理解语言"，是我们找到了一种把关系变成几何的方法
- **鉴定**：重组（分布式语义假说早在 1950 年代就有了）

#### EP03｜机器怎么"学会"：从下山到显卡

- **钩子**：为什么 AI 的参数总是 4096、128 这种数字？
- **主线**：y = kx + b；参数；训练就是"蒙着眼下山"（梯度下降）；推理；为什么要"深"（非线性）
- **往下挖**：Rosenblatt 感知机 1958（《纽约时报》说它将来"能走路、说话、有自我意识"）→ Minsky 1969 XOR 判了死刑 → AI 寒冬 → 反向传播 1986 → AlexNet 2012 用游戏显卡 → Transformer 2017
- **哲学**：Polanyi「我们知道的比说得出来的多」——为什么规则写不完，只能学；Hooker「硬件彩票」
- **内行彩蛋**：warp = 32、Tensor Core 分块、nanoGPT 词表补到 50304 提速约 25%
- **带走的念头**：一个思想能不能赢，常常要等硬件站到它那边
- **鉴定**：真新（规模带来的能力是真的意外）——全季第一个"真新"，建立鉴定标尺的可信度

### 第二幕：从"说"到"做"

#### EP04｜AI 没有手：Tool Calling

- **钩子**：AI 帮你订了机票——但它从头到尾只输出了文字，是谁按下了按钮？
- **主线**：结构化输出；JSON；函数与参数；「模型只说，程序去做」
- **往下挖**：子程序（EDSAC，1949 年前后的 Wheeler Jump）→ 函数 → API → RPC（Birrell & Nelson 1984）
- **哲学**：奥斯汀《如何以言行事》——有些话一说出口就是行动；Tool Call 是模型的"施事话语"
- **贯穿项目**：让 AI 调用转录工具和 FFmpeg
- **带走的念头**：AI 获得的不是"能力"，而是调用别人能力的"嘴"
- **鉴定**：重组

#### EP05｜循环：一个程序何时开始"自己做事"

- **钩子**：你让 AI 修 bug，它自己跑了 20 轮——谁决定它什么时候停下？
- **主线**：观察 → 思考 → 行动 → 再观察；ReAct；Planner / Executor；终止条件交给模型
- **往下挖**：维纳《控制论》1948 与"舵手"；恒温器；Shakey 机器人（1966–72）与 STRIPS 规划
- **哲学**：图灵停机问题——数学已证明"何时停"无法被普遍判断；我们今天把它交给了一个概率系统。控制权的转移
- **贯穿项目**：AI 反复修改文稿直到"满意"——它的"满意"是谁的标准？
- **带走的念头**：Agent = 把"何时停"交给模型的循环；这既是能力的来源，也是风险的来源
- **鉴定**：重组（反馈循环）+ 真新（能处理开放式目标的判断者）

#### EP06｜为什么 AI 又回到了命令行

- **钩子**：人类花了 50 年发明鼠标和触屏，最强的 AI 却在黑窗口里敲命令
- **主线**：终端；一切皆文本；stdin/stdout/stderr；管道；组合
- **往下挖**：Engelbart 1968「所有演示之母」与 GUI 之路；Unix 1969；McIlroy 的"花园水管"备忘录；Unix 哲学
- **三个原因**：模态匹配（文本进文本出）；可组合；**训练数据里充满了 shell 和 man page**（回扣 EP03：模型会什么，取决于它读过什么）
- **反方**：也有直接看屏幕、点鼠标的 Computer Use Agent——两条路线谁会赢？
- **哲学**：给人的界面与给机器的界面；海德格尔的"上手"——工具顺手时隐形，出错时才现身（错误信息正是 Agent 的眼睛）
- **带走的念头**：文本是最古老的接口，也可能是最通用的
- **鉴定**：旧物新用

### 第三幕：给 AI 造一个工作环境

#### EP07｜MCP：协议的价值不在技术，而在共识

- **钩子**：为什么每接一个新工具，都要重写一遍对接代码？
- **主线**：M×N 集成问题；Client / Server；工具发现；"写给模型看的说明书"
- **往下挖**：铁路轨距之争；集装箱（1956）；USB；LSP（2016）——MCP 的直系祖先；JSON-RPC
- **纠错点**：MCP 不等于远程调用，很多就跑在本机（stdio）
- **哲学**：标准化是技术问题还是政治/经济问题？谁定义标准，谁就定义生态
- **贯穿项目**：接入公众号、云盘、笔记工具
- **带走的念头**：MCP 的技术几乎全是旧的；新的是"读说明书的是一个模型"
- **鉴定**：重组（明确打这个标签，这正是你"旧瓶新酒"观点的主场）

#### EP08｜Skill：写给一个聪明但会偷懒的读者

- **钩子**：你的"90 分以上绿色"bug
- **主线**：上下文窗口是稀缺资源；渐进式披露；SKILL.md / references / scripts / assets；自然语言 vs 脚本的分工
- **往下挖**：内存层级与 Atlas 1962 的虚拟内存（按需分页 ≈ 按需加载 Skill）；模块化与 import；**专家系统与知识工程瓶颈**（第二次 AI 寒冬）
- **哲学**：Dijkstra《论"自然语言编程"之愚蠢》；Sutton《苦涩的教训》vs Skill 的回潮；Python 类型注解的历史——钟摆
- **贯穿项目**：把你的口播稿工作流写成一个 Skill
- **带走的念头**：Skill 是知识工程的第二次尝试；这次不同，是因为执行它的是一个能处理模糊情况的"解释器"
- **鉴定**：重组 + 真新（胶水层）

#### EP09｜马具：Harness 与 Sub-Agent

- **钩子**：同一个模型，放进不同的产品，能力差别为什么这么大？
- **主线**：Harness 词源（马具）；运行时；权限与沙箱；Plugin = 安装包；Sub-Agent 的核心是**上下文隔离**；异步与事件循环
- **往下挖**：操作系统的诞生（批处理 → 分时）；进程与线程；延迟尺度表（CPU 1 秒 → 网络 4 年 → 一次 LLM 调用 3000 年）
- **哲学**：《人月神话》——加 Agent 会不会像加人一样让项目更慢？康威定律——系统结构会复制组织结构
- **带走的念头**：模型是马，Harness 是马具；能跑多远，常常取决于马具
- **鉴定**：重组

## 第三部分：需要你拍板的问题

1. **"padding"是什么意思？** 贯穿项目是"剪视频"这个内容本身，还是一个用来调节每集时长的弹性段落？我按后者理解，并建议换成"用 AI 做这档节目"这个元项目。
2. **单集独立性**：发在小红书/B 站，很多观众会从中间某集点进来。要做成"每集可独立观看"（多一些回顾成本），还是"必须按顺序"（叙事更紧）？
3. **单集时长**：15 分钟、25 分钟还是 40 分钟？这决定每集能挂几个历史节点（我目前按每集 1–2 个设计）。
4. **"新旧鉴定"环节**：是否接受这个固定环节？它会成为系列的标志，但也会让你的判断更公开、更容易被挑战。
5. **时效性**：Skill、Plugin、Harness 这些名字可能一两年后就变了。是否接受"以思想为主角、产品名只当例子"，以免节目过时？
