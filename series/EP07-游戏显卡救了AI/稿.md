## 口播稿

### 一、钩子：这些数字为什么这么“整”

如果你看过大模型的技术参数，会发现一个很奇怪的现象：里面的数字特别“整”。隐藏层 4096，注意力头 32 个，批大小 128，词表大小 50304……

【配图 F01】一张模型配置文件的截图，把 4096、32、128、50304 这些数字圈出来。  （`figures/F01-参数为什么整.png`）

为什么不是 4000？为什么不是 33？

这个问题的答案，藏在一段很长的故事里。这个故事要从 2006 年讲起，主角有三个：一个做数据的教授，一个坚持冷门方向的老教授，还有一个卖游戏显卡的老板。

### 二、往下挖（一）：李飞飞和一千四百万张图

2006 年前后，刚刚开始独立做研究的**李飞飞**，看了很多当时的人工智能算法，发现一个问题：不管模型设计得多精巧、论文写得多漂亮，它都**没法泛化**。你训练它识别猫和狗，它就只会猫和狗，换成鸡和鸭就不灵了。

我们不可能为每一件事训练一个模型。那为什么人可以，模型不可以？

李飞飞给出的答案，在当时看起来很不主流：**因为模型看的数据太少了。**

那时候有多少数据？最经典的一个数据集叫 **MNIST**，是手写数字，0 到 9。它的来源跟邮政有关：美国需要机器自动识别信封上手写的邮政编码，于是把大量手写数字拍下来，做成 28 × 28 像素的黑白小图。

【配图 F02】MNIST 手写数字网格图：一片密密麻麻的 0–9。  （`figures/F02-MNIST.png`）

【校注】原话猜测是“联邦快递还是某家快递公司”。MNIST 的数据来自美国国家标准与技术研究院（NIST）收集的手写样本，最初的应用背景是美国邮政的邮编识别，也用于支票上的手写数字识别。

即便是这样一个简单的数据集，训练集也只有 6 万张。很多其他数据集只有几千张，甚至几百张。太少了，学不会。

李飞飞做了一个类比。一个小宝宝从出生到三岁，眼睛一直在看。如果把眼睛当成一个相机，每隔几百毫秒“拍”一张，到三岁时，他已经看过了几亿张“照片”。

所以她开始了一个在当时看起来很疯狂的项目：**ImageNet**。收集尽可能多的照片，然后请人一张一张地打上标签。

最后这个数据集有**一千四百多万张**图片，两万多个类别。不仅有“猫”，还分波斯猫、暹罗猫；不仅有“狗”，还分拉布拉多、哈士奇。标注靠的是亚马逊的众包平台，全世界成千上万的人一张一张地标。

【校注】原话说“收集了大概 300 万张，每张有 1000 多个分类”。ImageNet 全库约 1400 万张图、2 万多类；每年比赛用的是其中一个子集：**1000 个类别、约 120 万张训练图**。“1000 类”是比赛的类别数，不是每张图的标签数。

【配图 F03】ImageNet 的类别树：从“动物 → 哺乳动物 → 犬科 → 狗 → 拉布拉多”一层层展开，每层配几张缩略图。  （`figures/F03-ImageNet.png`）

有了数据，她又组织了一个比赛：大家用自己的算法来识别这些图，看谁的错误率低。

比赛办了两年，成绩一直在原地踏步，只有很小幅度的提升。

### 三、往下挖（二）：2012 年，一个来自多伦多的队伍

然后到了 2012 年。

来自加拿大多伦多大学的一个小队，把成绩一下子往前推了一大截。当时比赛常用的指标叫“top-5 错误率”，就是模型猜五次，五次里都没猜对才算错。第二名的错误率是 26%，这个队伍是 **15%**。

【校注】原话说“连续 5 年识别率在 60% 几徘徊，2012 年一口气提升 17 个点到 78”。按比赛官方数据：2012 年 AlexNet 的 top-5 错误率为 15.3%，第二名为 26.2%，领先约 11 个百分点。比赛始于 2010 年，到 2012 年是第三届。

这在比赛史上是一次碾压。据说李飞飞拿到结果的时候大喜过望，专门赶去了颁奖现场。

这个队伍用的是什么？就是那个被冷落了几十年的**神经网络**，加上反向传播。带队的是**辛顿**，动手的是他的两个学生，**亚历克斯·克里泽夫斯基**和**伊利亚·苏茨克维**。这个网络后来就以亚历克斯的名字命名，叫 **AlexNet**。

【配图 F04】辛顿、克里泽夫斯基、苏茨克维三人的合影；旁边一张柱状图：历年最好成绩的错误率，2012 年那根柱子陡然变矮。  （`figures/F04-AlexNet.png`）

【补充】伊利亚·苏茨克维后来成为 OpenAI 的联合创始人和首席科学家。这一张合影里，站着后来整个大模型时代的一部分起点。【/补充】

那问题来了：神经网络和反向传播，1986 年就有了。为什么偏偏到 2012 年才赢？

原因之一，是**算不动**。反向传播听起来简单精巧，但数据量一大，计算量是天文数字。

我们做个对比。也是 2012 年，谷歌的**吴恩达**团队做了一个很出名的实验，让神经网络看了一千万张从 YouTube 视频里截下来的图，最后神经网络自己“认出”了猫。这个实验用了一千台机器、**一万六千个 CPU 核心**，跑了三天。

【校注】原话说“吴恩达用了 3000 张 CPU 算了一周，猫和狗的图片大概 1200 张”。按公开资料：谷歌大脑 2012 年的“猫实验”用了 1000 台机器共 16000 个 CPU 核心，训练约 3 天，数据是 1000 万张 YouTube 视频截图。

而辛顿的学生呢？他们用了**两块游戏显卡**，在自己的卧室里，训练了五六天。

【校注】原话说“两周”。AlexNet 论文写的是用两块 GTX 580 训练了**五到六天**。

一边是一万六千个 CPU 核心，一边是两块游戏显卡。这个差距从哪来？

### 四、拆开它：CPU 和 GPU 到底差在哪

这时候就要请出第三位主角：**黄仁勋**和他的英伟达。

先说一下显卡是干什么的。显卡的任务是在屏幕上画画面，而屏幕本身就是一个天然的矩阵：一行行、一列列的像素。游戏里的每一帧，都需要对几百万个像素做差不多一样的计算。所以显卡天生就是做大量**矩阵运算**的。

**CPU** 像是一个博士，什么都会，特别擅长处理复杂的逻辑，大量的 if else 判断、分支跳转，它都能又快又准地搞定。但博士就那么几个人。

**GPU** 像是几千个小学生。每个人只会做简单的加减乘除，但人多。你给他们一大张乘法表，分下去，大家一起算，一下子就算完了。

【配图 F05】左边：一个戴眼镜的博士坐在桌前，面前是一张复杂流程图；右边：一个大礼堂，几千个小学生一人一张小纸条，同时低头做乘法。  （`figures/F05-CPU对GPU.png`）

为了让几千个小学生能一起干活，GPU 牺牲了大量处理复杂判断的能力。管理上也不能一个一个地管，太累了，所以它把**32 个线程编成一组**，一组一起听同一个指令、干同一类活。这一组在英伟达的术语里叫一个 **warp**，就是纺织机上的“经线”，一次织一排。

而神经网络的训练，说白了，绝大部分就是**矩阵乘法**。这个活，简直就是给 GPU 量身定做的。

【补充】为什么说神经网络的训练，“绝大部分就是矩阵乘法”？

还记得一个神经元在做什么吗：把输入加权求和，x₁·w₁ + x₂·w₂ + …。一层里有很多个神经元，每个神经元都做一次这样的加权求和。把所有神经元的权重排成一张表，这张表就是一个**矩阵** W；这一整层的计算，就是一次**矩阵乘以向量**：

> y = W · x

一个隐藏维度是 4096 的层，W 就是 4096 × 4096 的矩阵，大约 **1677 万**个数。算一次，就是 1677 万次乘法再加法。

衡量计算量有一个单位，叫 **FLOPs**，浮点运算次数。有一个很好用的估算：一个有 N 个参数的模型，每生成一个 token，大约需要 **2N** 次浮点运算。一个 70 亿参数的模型，生成一个字，就要算大约 **140 亿次**。训练的时候，还要把这个数乘以几万亿个 token，再乘以三（前向一次、反向约两次）。

这些运算有一个共同点：**彼此独立，可以同时算。** 第一行乘第一列，和第二行乘第二列，谁也不用等谁。这正是几千个小学生最擅长的活。

还有一个时代背景。2005 年前后，芯片行业撞上了一堵墙：以前，晶体管越做越小，CPU 的主频就能越来越高，单个核心每一两年就快一倍，这个规律叫**登纳德缩放**。可到了这个时候，晶体管再缩小，发热就压不住了，主频再也提不上去。于是整个行业被迫转向：**不再让一个核更快，而是放更多的核一起干。** 并行，从一种选择，变成了唯一的出路。

GPU 天生就是并行的。时代，站到了它这一边。【/补充】

【配图 F06】一张 4096 × 4096 的巨大网格（矩阵）和一根竖条（向量）相乘；镜头拉远，几千个小学生每人负责网格里的一行。旁边一条折线图：CPU 主频 1990–2005 年一路上升，2005 年后变平。  （`figures/F06-三颗龙珠.png`）

### 五、铲子太好，不知道挖什么

但这事在当年一点都不显然。

2006 到 2007 年，英伟达推出了一个叫 **CUDA** 的东西，让程序员可以用显卡去做通用计算，而不只是画游戏画面。

【校注】原话说“08 年的时候”，CUDA 于 2006 年底发布、2007 年正式推出。另外原话提到“老黄几乎把自己的别墅都抵押上去”，这个说法没有可靠出处，已删除。

那时候黄仁勋有一种危机感：游戏虽然好，但你做得再大，也是给别人打工，给微软打工，给索尼打工，给任天堂打工。显卡一定要有别的出路。

那 CUDA 能用来干什么呢？主要是科学计算。比如天气预报，比如空气动力学，比如把一个零件拆成无数个小单元，分析每个单元受力后怎么变形，也就是有限元分析。这些东西本质上也都是矩阵运算。

但你听一下，这些领域是不是比游戏还小众？如果你不是做精密机械设计或者天气预报的，你根本用不到这么高的算力。

有朋友说，这就是“**铲子太好，不知道给谁挖**”。学会了屠龙之术，却找不到龙。

于是英伟达做了一件事：到处给大学送卡，只要你申请，我就给你显卡。

然后，龙出现了。辛顿的学生拿着显卡，参加了李飞飞的比赛。**数据、算法、算力，三样东西在 2012 年第一次凑齐了**，就像集齐了七颗龙珠，终于召唤出了神龙。

【配图 F07】三颗龙珠依次亮起：ImageNet（数据）、反向传播 + 神经网络（算法）、GPU（算力），合在一起，一条龙腾空而起，龙身上写“2012”。  （`figures/F07-CUDA.png`）

所以最后，辛顿坚持了三十多年的方向，终于有了回报。2024 年，他和霍普菲尔德一起获得了诺贝尔物理学奖。至于英伟达和深度学习，谁成就了谁？我觉得只能说是**互相成就**。

### 六、回到钩子：为什么是 32、64、128

好，现在我们可以回答开头那个问题了。

GPU 是 32 个线程一组来干活的。如果你的计算正好是 32 的倍数，每一组都干得满满当当。如果你多出来一点，比如 33，那第二组就只有 1 个线程在干活，另外 31 个在旁边看着，但这一轮还是得跑。

【配图 F08】两排座位，每排 32 个：第一排坐满；第二排只坐了 1 个人，其他 31 个空座位打上灰色。标题：“33 的代价”。  （`figures/F08-32人一排.png`）

当然，实际情况比这更复杂一些。还有专门做矩阵乘法的 Tensor Core，它喜欢的分块大小，还有显存对齐等等，所以更常见的是 64、128 的倍数。但道理是一样的：**数字背后有硬件**。

有一个非常著名的例子。前 OpenAI 研究员卡帕西，有一个用来教学的迷你 GPT 项目，叫 **nanoGPT**。它原来的词表大小是 50257，一个很不整齐的数字。他把词表稍微补大一点，补到 **50304**，正好是 64 的倍数。多出来的那几十个词完全没用，但训练速度快了大约 **25%**。

【校注】原话为“nano ChatGPT”，应为 nanoGPT；“补成 32，或者说 64 的倍数”，50304 = 64 × 786，是 64 的倍数。

就这么明显。这是一个经典的**软件迁就硬件**的例子。

### 七、往上看：硬件彩票

这个故事背后，有一个很深刻的观点。2020 年，谷歌的研究者**萨拉·胡克**写了一篇文章，叫《**硬件彩票**》。

她的意思是：**一个研究想法能不能赢，往往不取决于它本身有多好，而取决于它是不是碰巧适配了当时的硬件。**

神经网络的想法 1950 年代就有了，反向传播 1986 年就有了，但它们一直“中不了奖”。直到有一天，一种本来为游戏设计的芯片，恰好最擅长做矩阵乘法，彩票才开出来。

那反过来想：**有没有一些很好的想法，因为不适配今天的 GPU，到现在还没中奖？**

【配图 F09】一张彩票：号码是“神经网络 1958”，刮开的奖区写着“中奖日期：2012，兑奖处：GPU”。  （`figures/F09-ScalingLaw.png`）

【补充】那“规模上去之后，出现了谁都没预料到的能力”，这句话有没有证据？

有，而且后来被研究得非常透。2020 年，OpenAI 的研究者发表了一篇论文，叫《神经语言模型的规模定律》。他们发现：模型的错误率（loss），随着参数量、数据量、计算量的增加，会**稳定地下降**，而且下降的方式非常有规律。把它画在对数坐标上，几乎是一条**直线**。这叫**幂律**。

这意味着：**你可以提前预测，把模型做大十倍，它会变好多少。** 规模，第一次从一种“赌博”，变成了一种可以计算的“投资”。

2022 年，DeepMind 又做了一个修正，叫 **Chinchilla**。他们发现，之前的大模型都“吃得太少了”：参数很多，读的数据不够。更好的配比，大约是**每个参数配 20 个 token 的训练数据**。一个 700 亿参数、读了 1.4 万亿个 token 的模型，打败了一个 2800 亿参数但数据不够的模型。

【配图 F10】对数坐标图：横轴是计算量，纵轴是 loss，一串点排成一条向右下方的直线；旁边一个小天平：“参数”和“数据”两头要平衡。  （`figures/F10-涌现反方.png`）

但是，这里有一个关键的争论。

规模定律说的是：loss **平滑地**下降。可人们在实际使用中看到的，常常是**突然**的变化：模型小的时候，某个能力完全没有；大到某个程度，这个能力一下子就“冒”出来了，比如做多位数加法、理解一个笑话。2022 年，有研究者把这叫作**涌现**。

2023 年，斯坦福的一篇论文提出了一个尖锐的反驳：**涌现，可能是测量方法造成的海市蜃楼。** 比如做五位数加法，如果评分标准是“全对才算对”，那模型从 60% 的位数对，进步到 90% 的位数对，分数都还是 0；直到它几乎每一位都对，分数才突然跳上去。可如果换一个平滑的评分标准，比如“对了几位”，那条曲线就是平滑上升的，根本没有“突然”。

所以，“量变引起质变”到底是真的，还是我们的尺子太粗？这个问题，到今天还在吵。【/补充】

【配图 F11】同一组数据，两种画法：左边用“全对才算分”，曲线在某一点突然跳起（涌现）；右边用“对了几位”，同一条曲线平滑上升。标题：“是能力在跳，还是尺子在跳？”  （`figures/F11-查族谱.png`）

### 八、查族谱

这一集，我想给一个不一样的标签。

数据、神经网络、GPU，单拿出来看，每一样都是旧的。但把它们放在一起，规模上去之后，出现了一种谁都没有预料到的能力。连辛顿的团队自己，都没想到会赢这么多。

这种“量变引起质变”的意外，我认为是真的：规模定律让“做大就会变好”变得可以预测，而 2012 年那一跳，也确实超出了所有人的预期。所以这一集的标签是：**新物种**。

但我必须把反方写在这里：如果“涌现”只是测量方法的错觉，那么规模带来的，也许只是“平滑地越来越好”，而不是一个“新物种”。这个判断，明年可能改判。

这也是全季第一个“新物种”。

1. ImageNet（李飞飞）给了数据，神经网络和反向传播（辛顿团队）给了算法，游戏显卡和 CUDA（英伟达）给了算力。2012 年 AlexNet 三样凑齐：top-5 错误率 26% → 15%。
2. 神经网络的一层就是 y = W·x，本质是大量彼此独立的乘加运算；N 个参数的模型每生成一个 token 约需 2N 次浮点运算。
3. CPU 像少数博士，GPU 像几千个小学生；2005 年前后登纳德缩放终结，并行成了唯一出路。
4. 数字背后有硬件：warp = 32 个线程，维度对齐到 64、128 的倍数能明显提速（nanoGPT 50304）。胡克的“硬件彩票”：想法能不能赢，常常取决于它是否适配当时的硬件。
5. 规模定律：loss 随规模按幂律下降，可以预测；Chinchilla：参数和数据要平衡（约 20 个 token 对应 1 个参数）。“涌现”是真的，还是测量的错觉？仍有争论。

## 总结

这一集讲的是一次“凑齐”。神经网络的想法等了五十多年，不是因为它错了，而是因为数据、算法和算力，从来没有同时站在它这边。2012 年，它们第一次站到了一起，而且后来人们发现，只要继续把规模做大，模型就会按一条可以预测的曲线变好。这是整个大模型时代的底层逻辑：规模。但规模到底只是让模型“更好”，还是让它“变成了别的东西”，这个问题，这一集留给了你，也留给了 EP17。下一集（EP08），我们看让规模真正发挥威力的那个结构：注意力。

## 内行彩蛋

- **warp 与 Tensor Core**：一个 warp 固定 32 个线程；Tensor Core 按矩阵块计算，不同代的 GPU 偏好 8、16、64 的倍数。实际调优时，隐藏层维度、词表、batch 大小对齐到 64 或 128 的倍数最常见。
- **nanoGPT 的 50304**：50304 = 64 × 786，原始 GPT-2 词表为 50257。卡帕西在推特上说，这是 nanoGPT 到目前为止“最戏剧性的一次优化”，而做法只是把词表补到最近的 64 的倍数。
- **AlexNet 的其他秘诀**：ReLU 激活、Dropout 防过拟合、数据增强、把网络拆到两块显卡上并行，都是这篇论文里的关键技巧。
